# Translation architecture

How a second locale is added to this site without touching a template. This is
the document `app/templates/partials/head.php` refers to for the hreflang
switch-on procedure. Referenced by BUILD-PLAN Phase 1.5 (plumbing) and
Phase 6 (content).

The 2026-08-19 audit confirmed the content layer is already cleanly separated
under `app/content/en/` — the blockers are all in the renderer and a handful of
stray strings. They are listed here so the plumbing PR (PR-04 in
`docs/PR-BATCHES.md`) is mechanical.

---

## 1. URL scheme

- English stays at the root: `/guides/residency/`. No `/en/` prefix, ever —
  moving launched English URLs would forfeit their equity for symmetry's sake.
- Every other locale is a prefix: `/es/guias/residencia/`, `/de/...`.
- **Localised slugs, not translated-in-place slugs.** Each locale has its own
  registry file with its own `url` values, so Spanish URLs can be Spanish.
  Route directories for a locale are generated by `tools/make-routes.php` from
  that locale's registry, exactly as English routes are today.

## 2. Content layout

```
app/content/
  en/   registry.php  navigation.php  global.php  pages/*.php
  es/   registry.php  navigation.php  global.php  pages/*.php   (Phase 6)
```

- Registry entries in every locale share the **same id** (`guides.residency`),
  which is what links translations to each other for hreflang and the
  language switcher. `url`, `title`, `description`, `h1`, `nav_label` are
  per-locale.
- A locale's page is `status => 'planned'` until its translation is written
  **and reviewed by that locale's own named reviewer, with its own review
  date**. The same code-enforced gate as English: planned pages render the
  in-preparation notice, stay `noindex`, stay out of the sitemap.
- A page may exist in one locale and not another. Nothing requires parity.

## 3. Renderer changes (the actual blockers)

Today `app/page-renderer.php` hardcodes `content/en/` in four places
(`registry()`, `navigation()`, `strings()`, and the content-file path in
`render_page()`), and no route passes a locale. The plumbing PR:

1. Gives `registry()`, `navigation()`, `strings()` and the content-file
   resolver a `string $locale = 'en'` parameter (static caches keyed by
   locale — the pattern is already keyed by path, so this is a rename).
2. Sets the current locale once in `bootstrap.php`/`render_page()`; route
   files for `/es/...` call `render_page('id', 'es')` — still two lines,
   still generated by `tools/make-routes.php`.
3. Threads locale through `page_url()`/`href()` so internal links stay inside
   the visitor's locale.
4. Derives from the locale instead of hardcoding: `<html lang>`,
   `og:locale` (`en` → `en_US` format while at it), and the three
   `'inLanguage' => 'en'` sites in `app/schema.php`.
5. `config/site.php` `'locales' => ['en']` (already present in the example
   config) becomes the single switch: a locale not in this array does not
   route, emit hreflang, or enter the sitemap.

## 5. hreflang and the language switcher — switch-on procedure

hreflang is emitted by `head.php` **only when** more than one locale in
`config` has a `live` page for the current id. Then, per such page:

- one `<link rel="alternate" hreflang="…">` per locale where that id is live,
  each pointing at that locale's canonical URL;
- `hreflang="x-default"` pointing at the English URL;
- reciprocity is automatic because both sides derive from the same registries.
  `tools/qa.php` gains a check: every hreflang target resolves to a live page
  in that locale, and pairs are symmetric.

The language switcher renders in the header **only when** a second locale is
configured, links to the *same page* in the other locale when it is live, and
to the other locale's home page when it is not (never to an in-preparation
notice). No automatic redirect by `Accept-Language` or IP — a visitor
researching a legal process must never be silently moved off the page they
chose; the switcher is the only mechanism.

## 6. Rules that do not bend

- **No machine-translated legal or tax content, ever.** A locale launches with
  a professional localisation, its own reviewer credential on the page, and
  its own review dates — or it stays `planned`. This is the same integrity
  gate as English, and it is enforced by the registry status field, not by
  intention.
- Sitemap includes a URL only for live pages of configured locales, same as
  today.
- The truthfulness rules (no invented numbers, placeholder suppression) apply
  per locale with no exceptions — a translation is a page, not a copy.
